# Синтаксический манифест md2gost

Статус: нормативный контракт нового синтаксиса. Изменения парсера, импорта,
рендера, preview, документации и примеров должны соответствовать этому файлу.
Справочник и примеры: [syntax.md](syntax.md). Правила разработки: [AGENTS.md](../AGENTS.md).

## Принципы

1. Содержание записывается обычным Markdown. Не переопределяем смысл его
   конструкций ради вёрстки: `---` — горизонтальная линия, `*…*` — курсив,
   вложенность списков задаётся отступами. Пустая строка не перезапускает список.
2. Основа — CommonMark с GFM-таблицами и зачёркиванием. Дополнительно поддерживаем
   TeX-математику, атрибуты, подписи, ссылки на объекты и контейнеры.
3. Существующий Markdown-элемент уточняется атрибутами. Контейнер нужен для
   генерируемой вставки или группы блоков, а не для каждой картинки и таблицы.
4. Автор задаёт смысл, система — номера и оформление. ГОСТ, шрифты, поля,
   правила подписей и продолжений остаются в YAML-конфиге с пресетами.
5. Одна потребность — одна запись. Новые возможности расширяют общие механизмы,
   не вводят новый префикс для каждого частного случая.
6. Неизвестные и неприменимые атрибуты, повторяющиеся ID, повреждённые контейнеры
   и неразрешимые автоссылки — ошибки, а не молчаливое исчезновение содержания.
7. Исходный код, строчный код и экранированный текст не интерпретируются как
   расширения. Изображения — ссылки на FS/S3, не встроенные данные.

## Атрибуты

Форма: `{#id .role key=value key2="значение с пробелами"}`.
ID и имена ролей начинаются с буквы либо `_`, далее допустимы буквы, цифры,
`_` и `-`. ID уникален во всём документе; ключи библиографии имеют отдельное
пространство имён. Повтор ID, роли или ключа в одном блоке — ошибка.

Атрибуты на строке заголовка относятся к заголовку; сразу после изображения —
к изображению. Отдельная строка атрибутов непосредственно после блока относится
к этому блоку. Она не может перескакивать через другой содержательный блок.
Для буквального текста экранируйте открывающую скобку: `\{…}`.

| Элемент | Атрибуты |
|---|---|
| Заголовок | `#id`, `.unnumbered`, `.appendix` |
| Изображение | `#id`, `width`, `height` |
| Таблица | `#id`, `widths`, `heights` |
| Листинг, Mermaid, блочная формула | `#id` |
| Нумерованный список | `#id`, `marker` |
| Абзац, маркированный список | `#id` |

`marker`: `arabic`, `lower-alpha-ru`, `upper-alpha-ru`, `lower-alpha-en`,
`upper-alpha-en`. Сами пункты всегда записываются обычными `1.` или `1)`.

Размеры изображений: положительное число с `%`, `cm`, `mm`, `pt`, `px`, `in`
либо `auto`. Одно измерение сохраняет пропорции; два явных могут их изменить.
`widths` — значения через запятую по числу столбцов, `heights` — по числу строк
включая шапку. Высота — минимальная, проценты для высот строк запрещены.

Подчёркивание — `[текст]{.underline}`. Внутри разрешены обычные строчные
выделения и код. Жирный, курсив, зачёркивание остаются `**…**`, `*…*`, `~~…~~`.

## Подписи

Одна форма после таблицы, листинга или Mermaid:

````markdown
```python
print("Пример")
```

: Простейшая программа {#example}
````

Допускается не более одной пустой строки между объектом и подписью. Тип объекта
определяет счётчик и формат подписи, а не префикс ID. Номер в подписи не пишется.
Атрибуты подписи относятся к объекту. Подпись без объекта и повторная подпись —
ошибки. Буквальный абзац с двоеточия записывается `\: …`.

Изображение сохраняет форму `![Подпись](image.png){#image}`. Размеры и ID
не извлекаются из Markdown title. Mermaid сохраняется fenced-блоком `mermaid`;
доступность графического рендера определяется реализацией сервиса, не синтаксисом.

## Ссылки и источники

- `[методика](#method)` — внутренняя ссылка с авторским текстом.
- `[](#method)` — автоматический текст ссылки на объект (тип и номер).
- `[@book]` — библиографическая ссылка. Повтор сохраняет номер источника.
- `[сайт](https://example.org)` — обычная внешняя ссылка.

Автоссылки поддерживают заголовки, приложения, изображения, таблицы, листинги,
блочные формулы. Ссылка может предшествовать объекту. Ненумерованный заголовок
цитируется названием. Обычная ссылка не превращается в автоссылку по эвристике.

Библиография — `::: {.bibliography}`, YAML-список источников, закрывающая `:::`.
Запись требует `id`; `type` необязателен. `text` задаёт готовое описание, иначе
описание собирается из `authors`, `title`, `city`, `publisher`, `year`, `url`.
Порядок и включение источников определяет конфиг.

## Контейнеры

Открытие: `::: {.role ...}`. Закрытие: отдельная строка `:::` той же длины.
Для вложенности внешняя ограда длиннее внутренней. Незакрытый контейнер — ошибка.

| Роль | Назначение и тело |
|---|---|
| `.template name="…"` | Зарегистрированный шаблон; тело — YAML mapping |
| `.bibliography` | Список источников; тело — YAML sequence |
| `.page-break` | Принудительный разрыв страницы; тело пустое |
| `.group` | Группа обычных Markdown-блоков без изменения оформления |

Простые параметры шаблона можно передать атрибутами. `true`/`false` и числа
типизируются; остальные значения остаются строками. Сложные данные — в YAML-теле.
Параметр не может одновременно присутствовать в атрибутах и теле. Имя шаблона
и его схема берутся из реестра; новый вузовский шаблон не меняет грамматику.

## Приложения

`# Исходные данные {.appendix}` открывает приложение до следующего заголовка
первого уровня. `##` внутри — первый локальный уровень, `###` — второй.
Следующий `# … {.appendix}` начинает следующее приложение. Обычный `# …`
возвращает документ к основной нумерации. `.appendix` допустим только у `#`
и несовместим с `.unnumbered`. Буквы и локальные номера формируются автоматически.

## Разрыв со старым синтаксисом

Совместимости и переключателя legacy-режима нет. `%table`, `%listing`,
`%diagram`, `%appendix`, `---content`, `---titlepage-…`, `@type:name`,
`++…++`, плоские `1.1.` и буквенные `а)` не являются расширениями.
Они разбираются только как обычный Markdown-текст. `# *…` больше не отключает
номер; fenced-блок `bibliography` — обычный листинг. Старые документы необходимо
переписать; импорт DOCX/PDF сразу выдаёт новый синтаксис.

## Правило изменения контракта

Сначала обновить этот манифест и acceptance-тесты. Затем изменить парсер,
валидацию, импорт и затронутые способы вывода; обновить справочник и фикстуры.
Обязательны unit, lint, typecheck и подходящие integration-проверки.
Изменения рендера проходят screenshot gate; падение требует ручного разбора,
автоматическое обновление эталонов для сокрытия отличий запрещено.
