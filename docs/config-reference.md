# Config reference

Единый YAML-конфиг описывает всё оформление документа. Базовый пресет выбирается полем `preset:`, точечные правки — в секции `overrides:`. Любое поле любого пресета можно переопределить.

```yaml
preset: gost-7-32-2017
overrides:
  font:
    size: 12pt
  page:
    margins:
      top: 3cm
```

Загрузка: `preset → user overrides → итоговая конфигурация` (deep merge), затем строгая валидация (`extra="forbid"`).

Размеры — строки с единицами: `cm`, `mm`, `pt`, `in`, `px`. Множитель межстрочного — число (`1.5`, `1.0`).

### `InlineCode`

Оформление инлайн-кода (`` `code` `` в markdown). По ГОСТ — моноширинный
Courier New кеглем основного текста или на 1–2 pt меньше (пресет задаёт
`13pt` при теле `14pt`, чтобы моноширинный шрифт не читался крупнее).
Цвет и заливка не настраиваются и не рендерятся никогда: чёрный текст на
белом фоне, без рамок. Для строгого нормоконтроля, запрещающего
моноширинные шрифты, — `quotes: true`: код оборачивается в «ёлочки».

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `font` | `str` | `Courier New` | Моноширинный шрифт для inline-кода |
| `size` | `str` | `14pt` | Размер шрифта (пресет ГОСТ — `13pt`) |
| `italic` | `bool` | `false` | Курсивное начертание |
| `quotes` | `bool` | `false` | Оборачивать в `«…»` |

## `captions`

Три отдельных стиля: `image`, `table`, `listing`. Все одного типа `CaptionStyle`.
`captions.continuation_break: true` включает ручной разрез таблиц с параграфом
`Продолжение таблицы N`; в native-режиме Word/LibreOffice сами переносят таблицу
и стабильно вставить такой параграф на автоматическом разрыве нельзя.

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `image` | `CaptionStyle` | см. ниже | Подпись под рисунком |
| `table` | `CaptionStyle` | см. ниже | Подпись перед таблицей |
| `listing` | `CaptionStyle` | см. ниже | Подпись перед листингом |
| `continuation_break` | `bool` | `false` | Ручной разрез длинных таблиц/листингов с подписью `Продолжение таблицы/листинга N` на стыке страниц |

### `CaptionStyle`

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `italic` | `bool` | `false` | |
| `bold` | `bool` | `false` | |
| `alignment` | `Alignment` | `left` | |
| `format` | `str` | `"{category} {number} — {text}"` | Шаблон, плейсхолдеры: `{category}`, `{number}`, `{text}` |
| `space_before` | `str` | `0pt` | Вертикальный отступ перед параграфом подписи (`paragraph_format.space_before`). Для caption-ов **перед** блоком (table) перетирается значением `table.space_before`, если оно задано |
| `space_after` | `str` | `0pt` | Вертикальный отступ после параграфа подписи. У image-caption (подпись после картинки) задаёт зазор между подписью и следующим текстом |
| `line_spacing` | `float \| null` | `null` | Множитель межстрочного внутри подписи. `null` — наследовать базовый интервал документа; ГОСТ/МИРЭА пресеты задают `1.0` |

В `default`: `image` центрируется (`alignment: center`), `table` и `listing` выравниваются влево.

## `lists`

| Поле | Тип | По умолчанию |
|------|-----|--------------|
| `mode` | `native` \| `inline` | `native` |
| `bullet_marker` | `str` | `—` (em-dash, U+2014) |
| `bullet_nested_format` | `str` | `{n})` — маркеры уровней 2+ bullet-списков |
| `numbered_format` | `str` | `{n}.` (fallback, см. ниже) |
| `alphabetic_format` | `str` | `{a})` (placeholder `{a}` — русская строчная буква) |
| `indent_left` | `str` | `1.25cm` |
| `indent_first_line` | `str` | `0cm` |
| `indent_per_level` | `str` | `0.75cm` |

`mode: native` (дефолт): bullet и arabic списки рендерятся нативной нумерацией Word — параграфы несут `w:numPr`, форматы маркеров и геометрия (висячий отступ маркера в зоне абзацного отступа) живут в `numbering.xml`. На каждый список выдаётся свежий `w:num`, поэтому нумерация не продолжается между соседними списками; вложенные уровни делят один num (`ilvl` = глубина). Bullet-цепочка: «—» на первом уровне, глубже — `1)`, `2)` (`bullet_nested_format`). `mode: inline` возвращает литеральные маркеры в тексте параграфа (совместимость со старым рендером).

Буквенные списки (`а)`, `б)`, …) всегда рендеруются литеральными маркерами даже в native-режиме: ГОСТ 7.32-2017 исключает буквы `ё, з, й, о, ч, ъ, ы, ь`, а последовательности нумерации Word такой фильтр не выражают. Отступы — те же, что у native-списков.

Для arabic-списков delimiter (`.` или `)`) — источник истины из md. Если автор пишет `1. текст` → рендер `1.`; если `1) текст` → рендер `1)`. Иерархические маркеры наследуют delimiter своего уровня: `1.` → `1.1.` → `1.1.1.` или `1)` → `1.1)` → `1.1.1)`. Конфиг `numbered_format` остаётся как fallback и в актуальной версии для arabic не применяется (md литерал перетирает).

Иерархическая нумерация для nested ordered-списков — поведение по умолчанию (не конфигурируется): уровни разделяются точкой (`1.1.1.` или `1.1.1)`), финальный delimiter берётся из литерального маркера на этом уровне. Цепочка прерывается на non-arabic предке (bullet/alpha) — глубже него нумерация снова локальная.

Иерархический список можно записать в одной из двух эквивалентных форм:

```markdown
# Форма A — стандартный MD nesting (отступы)
1. Уровень один
   1. Уровень два
      1. Уровень три

# Форма B — flat с явными dotted-маркерами
1. Уровень один
1.1. Уровень два
1.1.1. Уровень три
```

Парсер обе формы сворачивает в одинаковый AST. Литеральные числа маркера в форме B выбрасываются — нумерация делается рендером по факту порядка items.

Буквенная нумерация активируется автоматически: если в исходнике подряд идут параграфы вида `а) текст`, `б) текст`, ... — парсер сворачивает их в `ast.List` с буквенным `marker_style`. Маркер форматируется через `lists.alphabetic_format` (плейсхолдер `{a}` подставляется буквой того же алфавита, что и распознанный маркер).

Поддерживаются 4 алфавита, выбирается по букве первого пункта:

- `lower-alpha-ru` — `а..я` без `ё, з, й, о, ч, ъ, ы, ь`
- `upper-alpha-ru` — `А..Я` без `Ё, З, Й, О, Ч, Ъ, Ы, Ь`
- `lower-alpha-en` — `a..z`
- `upper-alpha-en` — `A..Z`

Внутри одного списка буквы должны идти подряд по одному алфавиту в одном регистре — иначе последовательность не распознаётся как alpha-список.

## `equation`

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `space_before` | `str` | `0pt` | Вертикальный отступ перед формулой. ГОСТ/МИРЭА пресеты задают `21pt`, что соответствует одной пустой строке при 14 pt и интервале 1.5 |
| `space_after` | `str` | `0pt` | Вертикальный отступ после формулы |
| `numbering_alignment` | `Alignment` | `right` | Выравнивание номера в правой ячейке формулы |
| `parentheses` | `bool` | `true` | Оборачивать номер в круглые скобки |

Блочная формула рендерится одной невидимой DOCX-таблицей: если отступы
ненулевые, верхняя и нижняя строки задают их высоту; строка с содержимым
содержит формулу по центру и номер справа.
OMML получает `w:sz`/`w:szCs` из `font.size`; LibreOffice/unoserver может
визуально уменьшать формулы при PDF-конвертации, поэтому размер формул в PDF
считается best-effort ограничением native OMML.

## `bibliography`

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `citation_format` | `str` | `"[{n}]"` | Шаблон inline-ссылки на источник; плейсхолдер `{n}` — номер источника |
| `order` | `citation \| input` | `citation` | `citation` — только процитированные источники в порядке первого цитирования; `input` — все источники в порядке YAML-списка |
| `style` | `minimal-gost` | `minimal-gost` | Минимальный расширяемый форматтер библиографического описания |
| `entry_number_format` | `str` | `"{n}."` | Шаблон номера в списке источников; плейсхолдер `{n}` — номер источника |

`minimal-gost` не является полноценным CSL-движком. Если у источника есть поле
`text`, оно выводится как готовое описание без изменений после номера. Иначе
описание собирается из известных полей: `authors`, `title`, `city`, `publisher`,
`year`, `url`.

## Добавление нового пресета

1. Создать `src/md2gost/config/presets/<name>.yaml` с любыми полями (отсутствующие наследуют дефолты схемы).
2. Использовать как `preset: <name>` в пользовательском конфиге или `--config <name>` в CLI.

Хардкод значений в коде ядра запрещён (см. [ADR-0004](adr/0004-config-presets.md)).

## UI-метаданные на полях

Лейблы (`title`), описания (`description`) и группы (`x-group`/`x-order`) задаются прямо в `src/md2gost/config/schema.py` через аргументы `Field(...)` — это единый источник правды и для бекенда (валидация), и для фронта (генерация формы).

Список секций для UI декларируется в `_CONFIG_GROUPS` рядом с `Config` и попадает в корень JSON Schema как `x-groups`. Любое **новое поле обязано** иметь `title` и `description` на русском, иначе оно появится в форме безымянным.

HTTP-ручки:

- `GET /api/config/schema` — JSON Schema конфига со всеми лейблами.
- `GET /api/config/presets` — список встроенных пресетов с уже резолвнутыми значениями (`{name, values}`).
